## Overview

**Project:** `twikiojcklvvuttbrijr` (Roule Rodrigues — live scooter-rental + local marketplace platform). Postgres via Supabase. **35 tables** in `public`, all with RLS enabled. **40 functions/RPCs**, **19 triggers**, **0 Edge Functions**, **91 migrations** (latest `20260806103324_m9_status_paid_captures_payment`).

> **Food platform (M50–M54, Aug 2026) — added after this audit was generated.**
> Five tables (`food_kitchens`, `food_kitchen_ops`, `food_items`,
> `food_categories`, `food_item_categories`), one view (`food_catalog`) and
> eight functions. The model is **a kitchen IS a store, a dish IS a product** —
> the same reuse decision M33 made for events, so food orders inherit
> `create_order()`, the row-locked stock reservation, the cash/bank handshake,
> guest checkout, the pickup code and the delivery network unchanged.
>
> Three things a newcomer will otherwise get wrong:
> * **`food_kitchen_ops` has RLS on and NO policy, deliberately.** It holds the
>   cooker's name and phone. RLS filters rows and never columns, and a table
>   grant makes column REVOKEs a no-op here — so the split table is the only
>   thing protecting that number. Do not add a policy, and do not move those
>   columns into `food_kitchens`, which anon can read.
> * **Every kitchen belongs to ONE system merchant (`system_key = 'food'`).**
>   A merchant per cooker mints a working merchant dashboard as a side effect of
>   `merchants.owner_id`, which is the exact trap M40 documented for organisers.
> * **`admin_update_order_status()`, `admin_preview_pickup_code()` and
>   `admin_redeem_pickup_code()` exist because `/admin` has a cookie session and
>   no `auth.uid()`.** The merchant-facing originals open with
>   `if auth.uid() is null then raise` and are unreachable from there. The admin
>   doors carry the same state machine and the same single-use guarantees, and
>   the two pickup ones additionally refuse any order that is not a kitchen
>   order — so the food operator can never close a merchant shop's sale.
>
> Dish availability is enforced by a **trigger on `order_items`**
> (`enforce_food_item_servable`), not inside `create_order()`, so it covers
> every writer that will ever exist and survives that RPC being rewritten.

The schema spans two generations: an original **v1 lead-gen / rental site** (bookings, contact, reviews, taxi, marketplace *listings*) and a newer **v6–v9 full commerce marketplace** (merchants, stores, products, orders, payments, subscriptions) built on Supabase Auth with a `SECURITY DEFINER` RPC layer. Cash / bank-transfer / QR are the marketplace payment rails; card providers are explicitly rejected in `create_order` (migration `m6_create_order_uses_shared_order_amounts` / `create_order_reject_card_providers`), consistent with the "cards are rentals-only" business rule.

### RLS design in one paragraph

Anonymous (`anon`) users can only **INSERT** into public intake tables (bookings, contact, waitlist, reviews, lead events, owner applications, place bookings — most gated to `status='pending'`) and **SELECT** a narrow set of public-facing content (active marketplace listings, active taxi drivers, approved reviews, site content, delivery zones, marketplace settings). Everything in the commerce core is gated by three `SECURITY DEFINER` helper predicates — `is_platform_admin()`, `is_store_staff(store_id)`, `is_merchant_staff(merchant_id)` — plus visibility helpers `store_is_visible()` / `merchant_is_approved()`. Customers see only their own `orders`/`payments`/`notifications` (`customer_id = auth.uid()` / `recipient_id = auth.uid()`). Write paths on orders/stock/payments/hours are funneled through RPCs rather than direct table DML.

## Bookings / Rentals (v1 core)

### `bookings` (2 rows)
Scooter rental reservations from the public site. **PK** `id` (uuid). Key cols: `name`, `email`, `phone`, `scooter`, `start_date`/`end_date` (date), `days` (int), `total_price` (text), `total_amount` (int), `status` (text), `partner_code`, `delivery_fee`, `deposit_amount`/`deposit_pct`/`deposit_paid_at`, `paypal_capture_id`, asset tracking (`asset_id`, `asset_label`, `pickup_time`, `return_time`), reminder flags (`pickup_reminded`, `return_reminded`, `feedback_reminded`). No FKs (partner link is by text `partner_code`, not enforced). **RLS:** `bookings_anon_insert` — anon may INSERT only with `status='pending'`; no anon SELECT/UPDATE (staff/admin read paths are via service role / admin, not a public policy).

### `place_bookings` (0 rows)
Bookings for "places" (stays / eat / do experiences in `/explore`). **PK** `id`. Cols: `place_id`/`place_name` (text), `category`, guest contact, `start_date`/`end_date`, `guests`, `quantity` (NN), `time_slot`, `deposit_amount`/`deposit_paid_at`/`paypal_capture_id`, `status`, `reminded`/`feedback_reminded`. **RLS:** `place_bookings_anon_insert` — anon INSERT with `status='pending'` only.

### `contact_submissions` (0 rows)
Contact-form intake. **PK** `id`. Cols: `name`, `email`, `phone`, `scooter`, `dates`, `message`, `handled` (bool, default false). **RLS:** `contact_anon_insert` — anon INSERT (`with_check true`); no public read.

### `waitlist` (0 rows)
Email capture. **PK** `id`. Cols: `email` (NN), `name`, `source`. **RLS:** `waitlist_anon_insert` (`with_check true`); no public read.

### `product_reviews` (7 rows) — *scooter* reviews (v1, distinct from marketplace `reviews`)
Testimonials for rental scooters. **PK** `id`. Cols: `scooter_id`/`scooter_name` (text), `name` (NN), `origin`, `rating` (int), `text`, `status`. **RLS:** `reviews_anon_insert` (INSERT `status='pending'`), `reviews_anon_select_approved` (SELECT `status='approved'`).

## Marketplace / Commerce (v6–v9 core)

### `merchants` (1 row)
Top-level seller entity. **PK** `id`. **FK** `owner_id → auth.users.id`. Cols: `legal_name`, `display_name`, `contact_email` (enum/domain type), `contact_phone`, `status` (enum), `kyc_status` (enum), `kyc_documents` (jsonb), `commission_rate` (numeric), `payout_details` (jsonb), `metadata` (jsonb). **RLS:** `merchants_read` (staff of merchant or admin), `merchants_insert` (`owner_id = auth.uid()`), `merchants_update` (owner or admin). One-shop-per-owner enforced by migration `merchant_one_shop_per_owner`. **Trigger** `t_merchant_provision_owner` (AFTER INSERT → `provision_merchant_owner()`), `t_merchants_updated` (BEFORE UPDATE → `set_updated_at`).

### `merchant_staff` (1 row)
Staff-to-merchant membership + role. **PK** `id`. **FKs** `merchant_id → merchants.id`, `user_id → auth.users.id`. Cols: `role` (enum), `permissions` (jsonb). **RLS:** `staff_read` (self, fellow merchant staff, or admin), `staff_write` (merchant owner via `merchants.owner_id = auth.uid()`, or admin).

### `stores` (1 row)
Storefront under a merchant. **PK** `id`. **FK** `merchant_id → merchants.id`. Cols: `name`, `slug` (enum/domain), `tagline`, `description`, `logo_url`, `cover_url`, `status` (enum), `category_hint`, `phone`/`whatsapp`/`address`, `lat`/`lng`, `currency` (char), `tax_inclusive`, `default_tax_rate`, `pickup_config` (jsonb), `fulfillment` (jsonb), `rating_avg`/`rating_count`. **RLS:** `stores_public_read` (admin, store staff, or `status='active' AND merchant_is_approved(merchant_id)`), `stores_staff_write` (staff or admin). **Triggers:** `t_stores_require_subscription` (BEFORE UPDATE → `enforce_active_subscription`), `t_stores_updated`.

### `store_hours` (7 rows)
Weekly + date-override schedule incl. separate delivery windows. **PK** `id`. **FK** `store_id → stores.id`. Cols: `weekday` (smallint), `date`, `opens_at`/`closes_at`, `is_closed`, `note`, `delivery_opens_at`/`delivery_closes_at`/`delivery_closed`. **RLS:** `store_hours_read` (visible store, staff, or admin), `store_hours_write` (staff or admin). Written via RPCs `set_store_hours` / `admin_set_store_hours`. **Trigger** `t_store_hours_updated`.

### `store_payment_settings` (1 row)
Per-store payment/fulfillment toggles + bank details. **PK** `store_id`. **FK** `store_id → stores.id`. Cols: `accepts_cash`, `accepts_bank_transfer`, `bank_name`, `account_holder`, `account_number`, `payment_instructions`, `require_receipt`, `offers_rr_delivery`, `offers_pickup`, `offers_customer_delivery`. **RLS:** `store_payment_settings_customer_read` (role `authenticated`; visible store/staff/admin) + `store_payment_settings_staff_write` (staff/admin). Note: **bank account fields are readable to any authenticated user of a visible store via this policy** — sensitive detail is instead meant to be fetched through order-scoped RPC `store_bank_details()` (migration `m8_bank_details_order_scoped`); the broad read policy is worth reviewing (to confirm intended).

### `categories` (8 rows)
Product taxonomy (self-referential). **PK** `id`. **FKs** `parent_id → categories.id`, referenced by `products.category_id`. Cols: `name`, `slug` (enum), `icon`, `position`, `is_active`. **RLS:** `categories_public_read` (`is_active OR is_platform_admin()`), `categories_admin_write` (ALL, admin).

### `products` (1 row)
**PK** `id`. **FKs** `store_id → stores.id`, `category_id → categories.id`. Cols: `name`, `slug`, `brand`, `description`, `status` (enum `product_status`), `has_variants`, `min_price` (int), `currency`, `tax_rate`, `attributes` (jsonb), `seo` (jsonb), `search_vector` (tsvector). **RLS:** `products_public_read` (admin, store staff, or `status='active' AND store_is_visible(store_id)`), `products_staff_write`. **Triggers:** `t_products_require_subscription` (INSERT/UPDATE → `enforce_active_subscription`), `t_products_updated`.

### `product_variants` (1 row)
Sellable SKUs + stock. **PK** `id`. **FK** `product_id → products.id`. Cols: `sku`, `barcode`, `name`, `options` (jsonb), `price` (int NN), `compare_at`, `cost`, `weight_grams`, `stock_quantity` (NN), `low_stock_threshold`, `is_active`, `position`, `unit`, `sold_by` (NN). **RLS:** `variants_read` (any viewer of parent product), `variants_write` (store staff/admin via parent product). **Triggers:** `t_variant_min_price` (INSERT/UPDATE/DELETE → `sync_product_min_price`), `t_variants_updated`.

### `product_media` (0 rows)
**PK** `id`. **FKs** `product_id → products.id`, `variant_id → product_variants.id`. Cols: `kind` (enum), `url` (NN), `alt`, `position`. **RLS:** `media_read` (any viewer of parent product), `media_write` (store staff/admin). Written via RPC `add_product_media`.

### `inventory_movements` (1 row)
Stock ledger. **PK** `id`. **FKs** `variant_id → product_variants.id`, `order_id → orders.id`, `created_by → auth.users.id`. Cols: `delta` (int), `reason` (enum `movement_reason`), `note`. **RLS:** `inventory_read` (store staff/admin via variant→product), `inventory_staff_insert` (staff/admin AND `reason <> 'sale'` — sales movements are system-only). **Trigger** `t_inventory_apply` (AFTER INSERT → `apply_inventory_movement`, applies delta to `stock_quantity`).

### `orders` (1 row)
**PK** `id`. **FKs** `store_id → stores.id`, `customer_id → auth.users.id`, `coupon_id → coupons.id`, `delivery_zone_id → delivery_zones.id`. Cols: `order_number` (NN), `status` (enum), money in integer minor units (`subtotal`, `discount`, `tax`, `total`, `delivery_fee`, `commission_amount`), `currency`, `pickup_slot` (tstzrange), `fulfillment_method`, delivery (`delivery_lat`/`lng`/`instructions`/`zone`), `payment_receipt_path`, `receipt_submitted_at`, `auto_release_at`, `internal_notes`, `notes`. **RLS:** `orders_read` (owning customer, store staff, or admin), `orders_staff_update` (staff/admin). Direct column writes are locked down (migrations `orders_column_grant_lockdown`, `m7_orders_column_select_lockdown`, `orders_status_rpc_only`) — status changes go only through `update_order_status` RPC; `internal_notes` is exposed only via `order_internal_notes()` RPC (staff-only). **Trigger** `t_orders_updated`.

### `order_items` (1 row)
**PK** `id`. **FKs** `order_id → orders.id`, `variant_id → product_variants.id`. Cols: `product_name` (NN), `variant_name`, `sku`, `unit_price`, `quantity`, `line_total`. **RLS:** `order_items_read` (owning customer, store staff, or admin via parent order). Insert is RPC-only (`create_order`).

### `payments` (1 row)
**PK** `id`. **FK** `order_id → orders.id`. Cols: `provider` (enum), `provider_ref`, `amount`, `currency`, `status` (enum), `raw` (jsonb). **RLS:** `payments_read` (owning customer or store staff/admin via order). Writes via RPCs `mark_order_paid` / `confirm_order_payment` / `mark_order_payment_failed` / `submit_payment_receipt`. **Trigger** `t_payments_updated`.

### `qr_pickup_tokens` (0 rows)
Hashed one-time pickup tokens. **PK** `id`. **FKs** `order_id → orders.id`, `redeemed_by → auth.users.id`. Cols: `token_hash` (NN — hash only, not raw), `issued_at`, `expires_at`, `redeemed_at`, `attempts`. **RLS:** `qr_read` (store staff/admin via order).

### `coupons` (0 rows)
**PK** `id`. **FK** `store_id → stores.id`. Cols: `code` (enum/domain), `discount_type`, `value`, `min_order`, `usage_limit`, `used_count`, `per_customer_limit`, `starts_at`/`expires_at`, `is_active`. **RLS:** `coupons_staff_read` + `coupons_write` (store staff or admin).

### `reviews` (0 rows) — marketplace store/product reviews (distinct from v1 `product_reviews`)
**PK** `id`. **FKs** `store_id → stores.id`, `product_id → products.id`, `order_id → orders.id`, `customer_id → auth.users.id`. Cols: `rating` (smallint), `title`, `body`, `status` (enum `review_status`). **RLS:** `reviews_public_read` (published, own, or staff/admin), `reviews_author_write` (INSERT `customer_id = auth.uid()`), `reviews_moderate` (UPDATE staff/admin). **Trigger** `t_review_store_rating` (INSERT/UPDATE/DELETE → `sync_store_rating` recomputes `stores.rating_avg/count`).

### `merchant_subscriptions` (1 row)
Subscription that gates selling (the canonical revenue model). **PK** `id`. **FK** `merchant_id → merchants.id`. Cols: `plan` (enum), `status` (enum), `started_at`, `current_period_end`, `grace_days`, `cancelled_at`, `note`. **RLS:** `merchant_subscriptions_read` (merchant staff/admin), `merchant_subscriptions_admin_write` (admin only). Consumed by `merchant_subscription_active()` / `store_subscription_active()` used in the `enforce_active_subscription` trigger.

### `subscription_invoices` (1 row)
**PK** `id`. **FK** `merchant_id → merchants.id`. Cols: `plan`, `amount`, `currency`, `period_start`/`period_end`, `status`, `paid_at`, `note`. **RLS:** `subscription_invoices_read` (merchant staff/admin), `subscription_invoices_admin_write` (admin).

## Security advisories

**From `get_advisors(security)`:**

- **WARN — Public/Signed-in can execute SECURITY DEFINER functions** (majority of the 40 functions, incl. the RLS predicates `is_platform_admin`, `is_store_staff`, `is_merchant_staff`, `store_is_visible`, and the trigger functions `handle_new_user`, `enforce_active_subscription`, `provision_merchant_owner`, `sync_store_rating`). Both `anon` and `authenticated` can call them via `/rest/v1/rpc/<name>`. The RLS predicates are low-risk (boolean, take a uuid), but **trigger functions like `enforce_active_subscription`, `handle_new_user`, `provision_merchant_owner`, `sync_store_rating` should NOT be RPC-callable** — `REVOKE EXECUTE ... FROM anon, authenticated` on all trigger functions, and audit each `admin_*` RPC to confirm it internally enforces `is_platform_admin()`. Remediation: https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable and https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable

For `partners` and `site_content_history`, confirm they are meant to be service-role-only; otherwise add explicit admin policies. Remediation: https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy

## Notes for the incoming engineer

- **Two review systems coexist:** v1 `product_reviews` (scooter testimonials, `scooter_id` text) vs marketplace `reviews` (FK-linked to stores/products/orders). Don't conflate.
- **Two "marketplace" concepts:** `marketplace_listings` (v1 flat directory) vs the `merchants`/`stores`/`products` commerce stack (v6+). New work is on the latter.
- **Money is integer minor units** everywhere in commerce tables (`orders`, `product_variants`, `payments`, `coupons`). `bookings.total_price` is legacy `text`.
- **Write discipline:** commerce mutations go through RPCs, not table DML — order status only via `update_order_status`, stock only via `inventory_movements` trigger, bank details only via `store_bank_details`. Preserve this; direct grants were deliberately revoked across many migrations.
- **`app_secrets`** holds server/bot secrets (accessed with the service-role key). Never surface its values or add a permissive policy. Env-var **names** referenced by the platform live in Vercel (PayPal creds, bot tokens per project memory) — values are not in this audit.
- **Unverified / to confirm:** no `platform_admins` rows exist yet; `pg_cron`/`pg_net` not installed so reminders run externally; the broad `store_payment_settings_customer_read` policy exposes bank columns to authenticated users of visible stores; each `admin_*` SECURITY DEFINER RPC's internal admin check was not read line-by-line in this audit.

See [ARCHITECTURE.md](./ARCHITECTURE.md) for how these tables are consumed by the API layer, auth flows, and marketplace pricing/security rules, and [NEXT_STEPS.md](./NEXT_STEPS.md) for the remediation backlog.
