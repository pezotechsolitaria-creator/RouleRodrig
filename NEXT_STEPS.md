## (a) Known issues / bugs to watch

- [ ] **`site_content_history` table is not in tracked migrations.** It is read/written by `app/api/cron/reminders/route.ts` and typed in `lib/supabase/types.ts`, but no `supabase/migrations/*.sql` creates it — it exists only in the live DB (schema drift; a fresh `db reset` would not recreate it). **(to confirm)** whether it's a manual/dashboard-created table.
- [ ] **The whole tourism/booking schema is un-migrated.** `bookings`, `place_bookings`, `contact_submissions`, `waitlist`, `lead_events`, `site_content`, `taxi_*`, `product_reviews`, `owner_applications`, `partners`, `marketplace_listings`, `marketplace_settings` are not in `supabase/migrations/` (that folder is marketplace-only). Their DDL/RLS lives directly in the live Supabase project. Capture them as migrations before any `db reset`. **(to confirm against live DB.)**
- [ ] **SW cache versioning is a manual step with no CI check.** Forgetting to bump `const CACHE = "rr-cache-vNN"` in `public/sw.js` re-introduces the stale-build "dead buttons on mobile" class of bug (currently `v94`).
- [ ] **`getPrivileged()` silently degrades** to the anon client when `SUPABASE_SERVICE_ROLE_KEY` is unset — only the subscription/store admin routes fail loudly (`hasServiceRole()` → 503). Other admin routes would behave differently (RLS-limited) if the key were missing. Watch after any env change.
- [ ] **`/api/owner-upload` is unauthenticated** and writes to the private `applications` bucket via the service-role client (rate-limited 15/60s, 4 MB, magic-byte checked). Anyone can deposit files there — confirm that is intended, or add a gate.
- [ ] **Rate limiting is in-memory and per-serverless-instance** (`lib/rate-limit.ts`) — not globally consistent. `admin-login` (5/5min) and booking guards are per-instance; a distributed store (`@vercel/kv` / Upstash) is the intended swap-in but is not wired.
- [ ] **Broad `store_payment_settings_customer_read` policy** exposes bank columns to any authenticated user of a visible store; the intended path is the order-scoped `store_bank_details()` RPC. Review the policy (flagged by the DB security audit).
- [ ] **RR012 depends on the checkout UI sending `expectedTotal`.** A new checkout path that omits it silently loses the "did the customer see this price?" guarantee. Any new checkout caller must forward it.
- [ ] **`/manage-booking`, `/partner`, taxi ratings** predate the v2 redesign — **(to confirm)** whether all are on the current design system.

**Notable bugs already fixed (do not regress):** mobile tap-jank (stale SW + per-card gyro listeners → single shared RAF-driven `deviceorientation` listener in `components/WhatLookingFor.tsx`); content-wipe on admin Save (mitigated by nightly `site_content_history` snapshot); booking-creation 500 from `.insert().select()` as anon; RR012 placement bug (guard compared against `v_total=0`); oversell-under-concurrency (row lock in `update_order_status` + stock-zero guard); `status='paid'` leaving `payments.status='pending'` (M9 repair).

## (b) Technical debt (with file references)

- [ ] **`create_order()` has been rewritten ~8+ times** (`create_order_rpc` → `v2` → `v3` → `v4_no_juice` → currency-cast/ambiguous-column/zone-aware/expected-total patches). Several later migrations rewrite the function by `pg_get_functiondef()` + `replace()` string surgery (e.g. `20260806101331`) that hard-fails if an anchor string isn't found. Clever and self-verifying but **fragile**: the canonical body isn't readable from any single file — you must replay the migration chain. Consider collapsing to one authoritative `CREATE OR REPLACE FUNCTION`.
- [ ] **60+ marketplace migrations in ~1 week**, many being fixes-to-fixes (`_fix_ambiguous_column`, `_correct_placement`, `_fix_currency_cast`). Excellent audit trail, hard to reason about — consider squashing to a clean baseline.
- [ ] **`MARKETPLACE.md` is partially stale** — it documents a **commission** model (`merchant.commission_rate`, commission-netting, payout) superseded by the **subscription** model, lists **PayPal / MCB Juice + QR-pickup** checkout that contradicts the shipped cash/bank-only rules, references a nonexistent `app/api/marketplace/qr/redeem/route.ts`, and prescribes a `features/` + `lib/marketplace/` layout that was never created (domain logic lives under `lib/merchant/`, `lib/orders/`, `lib/schemas/`, `lib/cart/`, `lib/notifications/`). Reconcile the doc to reality.
- [ ] **Commission plumbing remains after the model was dropped** — `orders.commission_amount` and `merchants.commission_rate` still exist; `create_order()` writes `commission_amount = 0`. Nothing reads it. Candidate for a clean-up migration.
- [ ] **Legacy enum values linger** — `payment_provider` still contains `'paypal'` and `'mcb_juice'` (Postgres has no `DROP VALUE`); unreachable for marketplace orders but present.
- [ ] **Two content systems + a legacy file coexist** — the JSONB `site_content` model (tourism) and the relational marketplace tables, plus a stale `content.json` at repo root. `lib/defaults.ts` (848 lines) is a large hand-maintained seed.
- [ ] **Two design systems coexist by design** (tourism dark/gold vs shadcn dashboard) — deliberate, but doubles the surface to keep consistent.
- [ ] **Environment-variable sprawl / duplication** (names only): both `NEXT_PUBLIC_SUPABASE_ANON_KEY` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (Supabase key-naming migration mid-flight); both `SUPABASE_SERVICE_ROLE_KEY` and `SUPABASE_SECRET_KEY`; both `RESEND_*` and `BREVO_*` (email-provider migration Resend→Brevo lingers); both `OWNER_PHONE` and `OWNER_WHATSAPP`. `FIRECRAWL_API_KEY` is in `.env.example` — **(to confirm)** still used. Produce a single audited env manifest.
- [ ] **CSP still allows `'unsafe-inline'`** on `script-src`/`style-src` (Next inline bootstrap + framer-motion inline styles; no nonce pipeline). Flagged in `next.config.ts` as future hardening.
- [ ] **Dependency cleanup candidates** — `@vercel/kv` (content moved to Supabase; no code imports it), `next-themes` (app is dark-only), root `content.json`, `app/v2/` (redirects to `/`). Owner calls on a live site, not safe to remove unilaterally.
- [ ] **DB security advisories** (from `get_advisors` — see [DATABASE_SCHEMA.md](./DATABASE_SCHEMA.md)): `REVOKE EXECUTE` trigger functions (`enforce_active_subscription`, `handle_new_user`, `provision_merchant_owner`, `sync_store_rating`) from `anon`/`authenticated`; audit each `admin_*` SECURITY DEFINER RPC's internal `is_platform_admin()` gate; confirm `partners`/`site_content_history` service-role-only intent; enable Supabase leaked-password protection.
- [ ] **DB performance advisories**: wrap per-row `auth.uid()` as `(select auth.uid())` in the 13 `auth_rls_initplan` policies; resolve the 61 `multiple_permissive_policies` overlaps; add covering indexes for the 4 unindexed FKs; revisit unused indexes after real traffic.
