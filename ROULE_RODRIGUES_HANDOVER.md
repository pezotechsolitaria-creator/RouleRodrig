## 1. Executive summary

Roule Rodrigues is a **mobile-first, installable-PWA booking platform and trip companion for Rodrigues Island** (a small island of Mauritius). Its revenue core is letting travelers **rent a scooter or car directly from local owners** — no booking fees, no middleman. Around that core it wraps a full "island OS": book places to **Stay · Eat · Do**, explore an **interactive island map** of beaches/viewpoints/landmarks, follow **scenic ride & hike routes**, generate a **free day-by-day trip itinerary**, ask **Ti Roulé** (a named AI island-guide mascot answering in English/French/Creole), reach a **WhatsApp food-and-table concierge**, find a **taxi/transport driver**, and — newest — shop a **local-merchant marketplace**.

Everything user-facing is **trilingual (en/fr/cr)** and **content-driven**: fleet, stays, tours, map locations, routes, events, copy, and home tiles all live in a single Supabase `site_content` JSONB row edited from `/admin`, with `lib/defaults.ts` only as a first-run seed (editing defaults does **not** change the live site). SEO is treated as a real acquisition channel — every page sets metadata, emits JSON-LD (`lib/schema.ts`, `components/JsonLd.tsx`), and uses ISR (`export const revalidate`).

**Live URL:** https://roulerodrig.com · **Core revenue model:** deposit-based scooter/car rentals (PayPal in EUR; balance settled on-island) plus a subscription-based merchant marketplace. **North star (from `PRODUCT.md`): "Success today = more rental bookings."** Every screen exists to earn a booking; the broad plan/explore/guide surface is there to win organic discovery and trust that funnel a visitor toward a paid rental.

## 2. Business goals & audiences

Scooter and car rentals are the core revenue; the surrounding content exists to funnel visitors into a paid booking ("every screen earns a booking").

| Audience | Who | What they do | Served by |
|---|---|---|---|
| **Primary — travelers (planning, pre-arrival)** | Researching from home, comparing & pre-booking | SEO guides, trilingual French landing pages, trip planner, rich island content | `/guide/*`, `/fr/*`, `/blog`, `/trip-planner`, `/explore`, `/map` |
| **Primary — travelers (on-island, phone-in-hand)** | Last-minute booking, navigating, asking, finding food/taxi | App-like PWA, live availability, Ti Roulé, food concierge, taxi, emergency numbers | `/`, `/browse/*`, `/taxi`, `/food`, `/emergency`, floating tab bar + `GlobalTiRoule` |
| **Secondary — local suppliers** | Scooter/car owners, guesthouses, tour operators, restaurants | List/apply to be on the platform | `/partner`, `/list-your-scooter` (growing supply is *not* the current primary objective) |
| **Secondary — local merchants (shops)** | Retail businesses selling products | Onboard, manage products/orders, get paid | `/merchant/**` (subscription-gated marketplace) |
| **Operator (the owner)** | Runs the whole business | Edit all content, manage bookings, approve merchants | `/admin`, `/admin/*` |

**Monetization models present:**
- **Rentals** — deposit-based (PayPal in **EUR**; balance settled on-island). Deposits computed server-side: scooter **25%**, car **50%**, place = owner-set flat (`lib/holds.ts`, `CLAUDE.md`).
- **Marketplace** — **subscription, not commission.** Plans `starter | standard | premium`; recurring auto-billing is **not** implemented (invoices are recorded manually today). Legacy `commission_rate`/`commission_amount` columns still exist but the live model is subscription.

## 3. Tech stack at a glance

- **Framework:** Next.js 16 (App Router, Turbopack) · React 19.2 · TypeScript 5 (`strict`)
- **Styling:** Tailwind v4 (CSS-first `@theme` in `app/globals.css`, no `tailwind.config.js`) · shadcn/ui primitives · framer-motion · lucide-react
- **Backend:** Supabase (Postgres + RLS + Auth + Storage) — three clients (browser, SSR/cookie, service-role)
- **Payments:** PayPal REST (EUR only) for rental/place deposits; marketplace is cash / bank transfer / manual
- **Hosting:** Vercel (auto-deploy from `main`) + Vercel Cron, Analytics, Speed Insights, Blob
- **Merchant dashboard stack:** TanStack Query + React Hook Form + Zod (scoped to `/merchant`, kept out of the tourism site)
- **Email/notifications:** Brevo (or Resend) for customer email; CallMeBot for owner-only WhatsApp alerts
- **Maps:** Leaflet / react-leaflet · **FX:** open.er-api.com (key-less)
- **PWA:** service worker (`public/sw.js`) + manifest (`app/manifest.ts`)
- **Testing:** Vitest (unit) + Playwright + axe-core (E2E + a11y)

## 5. Deploy & run

### Run locally
```bash
npm install
npm run dev        # http://localhost:3000
```
- PayPal `POST /api/paypal/create-order` returns **503 locally by design** — the creds live only in Vercel. Not a bug.
- Turbopack **dev** lags on newly-added arbitrary Tailwind classes (e.g. `h-[190px]`) until a full restart + SW cache clear. The production build generates all CSS correctly.
- Screenshots via the browser tools often time out — verify layout with `javascript_tool` measuring `getBoundingClientRect()` and reading the DOM.

### Deploy
```bash
npm run build      # MANDATORY before push — generates ALL Tailwind CSS
git push origin main   # → Vercel auto-deploys. There is no separate deploy step.
```
- **`main` is live production.** Push to it and it ships to roulerodrig.com.
- **MANDATORY on every deploy:** bump the service-worker cache in `public/sw.js` — increment `const CACHE = "rr-cache-vNN"` (currently `v94`). Skipping this strands users on a stale cached build (the "dead buttons on mobile" bug). There is no CI check enforcing it.
- Run `npm run build` and verify before pushing; there is no staging gate.

## 6. Development history highlights

The project is roughly **two products in one deployment**: (A) a trilingual tourism/booking site + AI island guide (June → late July), and (B) a full commerce **marketplace** (milestones M1–M9, end-July → early-August) grafted into the same Next.js/Supabase app. Reconstructed from ~253 commits (`0405813` → `83437ca`, 2026-06-04 → 2026-08-06).

**What's built:** the trilingual tourism site (rentals, Stay·Eat·Do, island guide/SEO, map, trip planner, taxi, food concierge, Ti Roulé), the admin CMS, and the marketplace merchant platform + admin. The customer storefront is partial (Phase 2). See [FEATURES_STATUS.md](./FEATURES_STATUS.md).

**Key decisions:**
- **Content model** — Supabase `site_content` JSONB (`id='main'`) overrides `lib/defaults.ts`; admin "Save" overwrites the whole blob; raw SQL edits don't stick.
- **Two booking flows** — vehicles (`bookings`) and places (`place_bookings`); deposits server-side, charged EUR via PayPal; first-to-pay-wins a vehicle.
- **Ti Roulé is LLM-free** — a rules/knowledge engine (`lib/rodrigues-knowledge.ts`), "nothing to bill and nothing to hallucinate."
- **Marketplace = modular monolith, subscription not commission, cash/bank/QR only, integer-minor-unit money, RLS-first with service-role owning payments/stock/QR.**
- **SEO as a channel** — per-page metadata, JSON-LD, ISR, server-rendered French `/fr/*` pages + hreflang, retired `vercel.app` host 308-redirected to `roulerodrig.com`.

**Notable bugs fixed (don't regress):**
- **Mobile tap-jank** — stale SW serving old HTML + per-card gyroscope listeners; fixed by SW cache-bump discipline and a single shared RAF-driven `deviceorientation` listener (`components/WhatLookingFor.tsx`).
- **Content-wipe on admin Save** — mitigated by a nightly snapshot into `site_content_history` (cron `0 6 * * *`), pruned to ~90 days.
- **Price integrity (RR012)** — `create_order()` refuses to charge a total the customer was never shown; the first fix was itself buggy (guard compared against `v_total=0`) and corrected in `20260806101331`.
- **Cert/DNS** — Cloudflare must stay grey-cloud "DNS only" or Vercel can't issue TLS.
- **SW cache versioning** — bump `rr-cache-vNN` every deploy.
- Plus: booking-creation 500 from `.insert().select()` as anon; oversell-under-concurrency (row locks + stock-zero guard); `status='paid'` leaving `payments` pending (M9 repair); vehicle-slug-in-email (`lib/vehicle-name.ts`).

## 7. Critical gotchas (read before touching anything)

- **Editing `lib/defaults.ts` does NOT change the live site.** The Supabase `site_content` row overrides it; defaults are only the first-run seed. Content changes go through `/admin`.
- **SQL writes to content get wiped on admin Save.** The admin "Save Changes" button overwrites the whole `site_content.data` blob. Never patch content with raw SQL and expect it to stick.
- **Bump the SW cache (`rr-cache-vNN` in `public/sw.js`) on every deploy.** Forgetting it strands users on a stale build.
- **Treat `main` as live.** Push = deploy to production. Always `npm run build` and verify first.
- **PayPal is EUR, and its creds live only in Vercel.** Local create-order returns 503 by design; MUR is not supported so deposits are charged in EUR.
- **Anon can INSERT but not SELECT.** Never use `.insert().select()` on the anon booking tables — the `RETURNING` trips RLS and breaks the insert. Generate `crypto.randomUUID()` server-side and insert plainly.
- **Ti Roulé mascot artwork is owner-supplied — never redraw or regenerate it.** Animate the existing 15 poses only.
- **Cloudflare DNS must stay grey-cloud ("DNS only").** Orange-cloud (proxied) breaks Vercel's ACME challenge and the TLS cert won't issue.

More invariants (RR012 price-integrity, column-grant lockdowns, the removed `kind:"order"` PayPal P0, the two admin identities) are documented in [ARCHITECTURE.md](./ARCHITECTURE.md) §12.
